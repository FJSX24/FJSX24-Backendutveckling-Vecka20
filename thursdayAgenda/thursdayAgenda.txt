Slide 2 – JWT Middleware

Middleware kontrollerar JWT-token vid varje request.

Varför middleware är smidigt och effektivt.

Talarmanus:
"En middleware är en funktion som körs innan våra route-handlers. Vi kan använda middleware för att kontrollera att användaren är autentiserad innan hen får åtkomst."

-----------------------------
Slide 3 – Middleware exempel

function verifyJWT(req, res, next) {
  const token = req.headers.authorization?.split(' ')[1];

  if (!token) return res.status(401).json({ error: "JWT-token saknas." });

  jwt.verify(token, process.env.JWT_SECRET, (err, payload) => {
    if (err) return res.status(403).json({ error: "JWT-token är ogiltig." });
    req.user = payload; 
    next();
  });
}

app.get("/protected", verifyJWT, (req, res) => {
  res.json({ user: req.user });
});

Talarmanus:
"Här ser ni hur vi praktiskt implementerar JWT-middleware i Express. Alla skyddade routes kan nu enkelt använda verifyJWT för att kontrollera token innan åtkomst ges."

-----------------------------
Slide 4 – Varför lösenordshashing (bcrypt)?

Lösenord får ALDRIG sparas i klartext.

bcrypt skyddar lösenord med hashing.

Talarmanus:
"Att spara lösenord i klartext är väldigt osäkert. bcrypt hjälper oss att lagra lösenord som säkra hashes, vilket gör lösenorden mycket svåra att knäcka vid intrång."

-----------------------------
Slide 5 – bcrypt.js exempel

import bcrypt from 'bcrypt';

// Hasha lösenord
const hashedPassword = await bcrypt.hash("lösenord123", 10);

// Kontrollera lösenord
const match = await bcrypt.compare("lösenord123", hashedPassword);

Talarmanus:
"Med bcrypt kan vi hash:a lösenord enkelt med funktionen .hash() och sedan kontrollera lösenord med .compare()."

-----------------------------
Slide 6 – Hashing & Saltning
Talarmanus:

”När vi sparar lösenord måste vi skydda dem ordentligt. Genom hashning gör vi lösenorden svåra att knäcka, och med saltning lägger vi till ett ytterligare skydd. bcrypt hanterar både hashning och saltning åt oss automatiskt."
